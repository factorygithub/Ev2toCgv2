# ConfigGen Project Structure

This directory contains the ConfigGen v2 implementation that replaces manually authored EV2 artifacts.

## Directory Structure

```
ConfigurationGeneration/
├── Topology/              # Service topology definitions
│   ├── Topology.cs       # Main topology (replaces ServiceModel.json)
│   └── Environments/     # Environment-specific configurations
│       ├── EnvironmentBase.cs
│       ├── Test.cs
│       ├── PPE.cs
│       ├── Production.cs
│       └── Fairfax.cs
│
├── Resources/            # Azure resource type definitions
│   ├── AksCluster.cs    # AKS cluster resource
│   ├── StorageAccount.cs # Storage account resource
│   ├── TableService.cs  # Table service resource
│   ├── EventHub.cs      # Event Hub resource
│   └── RoleAssignments.cs # RBAC role assignments
│
├── Manifests/           # Generated EV2 artifacts (output)
│   ├── ServiceModel.json     # Generated by ConfigGen
│   ├── RolloutSpec.json      # Generated by ConfigGen
│   ├── Templates/            # Generated ARM templates
│   └── Parameters/           # Generated parameters
│
└── Tests/               # Unit tests for validation
    ├── TopologyTests.cs
    └── ResourceTests.cs
```

## How It Works

### 1. Define Your Service Topology

**Topology.cs** is the main entry point. It defines:
- Service name
- Subscription mappings
- Resource groups per region
- Resources to deploy

Example:
```csharp
public class Topology : TopologyBase
{
    public Topology()
    {
        ServiceName = "MyAzureService";
        
        // Resolve subscription
        var subscription = Subscription.Resolve($"{ServiceName}-Prod");
        
        // Create resources for each datacenter
        foreach (var dataCenter in Environment.DataCenters)
        {
            var resourceGroup = new ResourceGroup
            {
                Name = $"{ServiceName}-{dataCenter.Region}-rg",
                Location = dataCenter.Region,
                Subscription = subscription
            };
            
            // Add resources...
        }
    }
}
```

### 2. Configure Environments

Each environment file (Test.cs, PPE.cs, Production.cs, Fairfax.cs) defines:
- Regions to deploy to
- Region capabilities (zones, SKUs, quotas)
- Compliance requirements (CMK, etc.)
- Environment-specific overrides

Example:
```csharp
public class Production : EnvironmentBase
{
    public Production()
    {
        Name = "Production";
        IsProduction = true;
        
        DataCenters.Add(new DataCenter
        {
            Region = "eastus",
            Zones = new[] { "1", "2", "3" },
            SupportsAks = true,
            MaxNodeCount = 10
        });
    }
}
```

### 3. Define Azure Resources

Resource classes in the `Resources/` directory provide type-safe definitions:

```csharp
var storage = new StorageAccount(
    name: $"{ServiceName}-{region}-sa",
    region: dataCenter.Region,
    resourceGroup: resourceGroup
);

// Apply environment-specific configuration
storage.ApplyConfiguration(environment, dataCenter);

// Generates ARM template
string armTemplate = storage.GenerateArmTemplate();
```

### 4. Generate EV2 Artifacts

When you build and run the ConfigGen project:

```bash
dotnet build ConfigurationGeneration.csproj
dotnet run --environment Production --output ./Manifests
```

This generates:
- `ServiceModel.json` - Region Agnostic EV2 service model
- `RolloutSpec.json` - Deployment orchestration spec
- `Templates/*.json` - ARM templates for each resource
- `Parameters/*.json` - Parameter files for each environment

### 5. Deploy with EV2

The generated artifacts are consumed by EV2 exactly as before:

```yaml
- task: EV2@1
  inputs:
    serviceGroupRoot: '$(Pipeline.Workspace)/Manifests'
    rolloutSpecPath: '$(Pipeline.Workspace)/Manifests/RolloutSpec.json'
```

## Key Concepts

### Region Agnostic

ConfigGen generates region-agnostic EV2 artifacts automatically. You define the logic once, and it applies to all regions.

**Before (Manual EV2):**
```
ServiceModel.eastus.json
ServiceModel.westus2.json
ServiceModel.northeurope.json
ServiceModel.italynorth.json
```

**After (ConfigGen):**
```csharp
// One definition
foreach (var dataCenter in Environment.DataCenters)
{
    // Apply to all regions
}
```

### Compile-Time Validation

Errors are caught during build, not deployment:

```csharp
// This won't compile if property doesn't exist
storage.MinimumTlsVersion = "TLS1_2";

// Type safety prevents errors
storage.Sku = environment.IsProduction ? "Standard_GRS" : "Standard_LRS";
```

### Environment Overrides

Different configurations for different environments:

```csharp
if (environment.IsProduction)
{
    NodeCount = 10;
    Sku = "Premium";
    EnableMonitoring = true;
}
else
{
    NodeCount = 2;
    Sku = "Standard";
    EnableMonitoring = false;
}
```

### Region-Specific Handling

Different configurations for different regions:

```csharp
if (dataCenter.Region == "italynorth")
{
    // Italy North has limited zone support
    Zones = new[] { "1", "2" };
    VmSize = "Standard_D4_v3"; // Specific SKU
}
else if (dataCenter.Cloud == CloudType.Fairfax)
{
    // Fairfax has compliance requirements
    RequiresCMK = true;
    VmSize = "Standard_D4_v3";
}
```

## Benefits

### 1. Single Source of Truth
- One topology definition for all regions
- Eliminates duplication and drift
- Easy to maintain consistency

### 2. Type Safety
- C# compiler catches errors
- IntelliSense for property discovery
- Refactoring tools work

### 3. Testability
- Unit test your configuration logic
- Validate region compatibility
- Mock environments for testing

### 4. Maintainability
- Add new regions in minutes
- Update SKUs globally with one change
- Region-specific overrides in one place

### 5. Reliability
- Compile-time validation
- No JSON syntax errors
- Consistent artifact generation

## Common Patterns

### Pattern 1: Adding a New Region

```csharp
// In Production.cs
DataCenters.Add(new DataCenter
{
    Region = "italynorth",
    Zones = new[] { "1", "2" },
    SupportsAks = true,
    MaxNodeCount = 8,
    RequiresCMK = true,
    KeyVaultUri = "https://keyvault-italynorth.vault.azure.net/"
});
```

**Time:** 30 minutes  
**Impact:** Compile-time validated, automatically included in next deployment

### Pattern 2: Global SKU Update

```csharp
// In Topology.cs or Resource class
VmSize = environment.IsProduction 
    ? "Standard_D8s_v3"  // Changed from D4s to D8s
    : "Standard_D2s_v3";
```

**Time:** 5 minutes  
**Impact:** All regions updated consistently

### Pattern 3: Region-Specific Override

```csharp
// In resource configuration method
if (dataCenter.Region == "italynorth")
{
    Capacity = 5; // Lower capacity for new region
}
else
{
    Capacity = 10; // Standard capacity
}
```

**Time:** 10 minutes  
**Impact:** Targeted override without affecting other regions

## Development Workflow

### 1. Local Development

```bash
# Make changes to topology or resources
vim ConfigurationGeneration/Topology/Topology.cs

# Build to validate
dotnet build

# Generate artifacts locally
dotnet run --environment Test --output ./LocalManifests

# Validate generated artifacts
cat LocalManifests/ServiceModel.json
```

### 2. Testing

```bash
# Run unit tests
dotnet test

# Validate with EV2 tools (if available)
ev2 validate --path ./LocalManifests
```

### 3. Pipeline Integration

```yaml
- task: DotNetCoreCLI@2
  displayName: 'Generate EV2 Artifacts'
  inputs:
    command: 'run'
    projects: '**/ConfigurationGeneration.csproj'
    arguments: '--environment Production --output $(Build.ArtifactStagingDirectory)'
```

### 4. Deployment

EV2 consumes generated artifacts:

```yaml
- task: EV2@1
  inputs:
    serviceGroupRoot: '$(Build.ArtifactStagingDirectory)'
```
